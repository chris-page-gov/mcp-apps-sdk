# MCP Apps SDK User Guide

## Overview
The MCP Apps SDK monorepo bundles all tooling required to render Model Context Protocol (MCP) apps inside agent surfaces. It contains four publishable packages (`@xalia/mcp-client`, `@xalia/mcp-apps-adapters`, `@xalia/mcp-apps-widget`, `@xalia/mcp-apps-sdk`) plus runnable examples under `examples/`.

## Prerequisites
- Node.js 18+
- pnpm 10+
- Python 3.11+ (needed for the Python MCP servers)
- A valid `OPENAI_API_KEY` exposed to the devcontainer (already forwarded via `.devcontainer/devcontainer.json`)

## Initial Setup
```bash
# install workspace dependencies
pnpm install

# build all packages via tsup
pnpm build
```

Useful validation commands:
```bash
pnpm lint        # eslint across packages
pnpm type-check  # tsc --noEmit for every workspace
```

## One-Command Demo (Recommended)
The root `package.json` exposes a convenience script that launches every moving part required for the chatbot example:

```bash
pnpm example:chatbot
```

This script performs the following in parallel:
1. Builds widget assets in `examples/openai-apps-sdk-examples` and serves them on **http://localhost:4444**.
2. Starts the Python solar-system MCP server on **http://localhost:8002** (using a virtual environment under the example folder).
3. Boots the Next.js chatbot on **http://localhost:3000**.

Press `Ctrl+C` in the terminal running the script to gracefully shut down all processes.
> The helper validates `OPENAI_API_KEY` by calling `https://api.openai.com/v1/models/gpt-4o` before it starts anything. If you see a 401/403 message, fix the key or grant access instead of rerunning blindly. Set `SKIP_OPENAI_KEY_CHECK=1` when you intentionally want to skip the test (for example, when you are offline).

## Manual Workflow
If you prefer to launch components individually:

### Widget Asset Server
```bash
cd examples/openai-apps-sdk-examples
pnpm install
pnpm run build   # regenerates assets/*.html
pnpm run serve   # serves on http://localhost:4444
```

> Always rebuild before serving; the MCP servers expect the hashed HTML generated by `pnpm run build`.

### Solar System MCP Server (Python)
```bash
cd examples/openai-apps-sdk-examples/solar-system_server_python
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --port 8002
```

### Pizzaz MCP Server (Node)
```bash
cd examples/openai-apps-sdk-examples/pizzaz_server_node
pnpm install
pnpm start   # defaults to http://localhost:8000
```

### Pizzaz MCP Server (Python)
```bash
cd examples/openai-apps-sdk-examples/pizzaz_server_python
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --port 8000
```

### Next.js Chatbot (Vercel AI SDK)
```bash
cd examples/chatbot
pnpm install
pnpm dev
```

Update `examples/chatbot/lib/mcpSetup.ts` if you need to point the chatbot at a different MCP server/port.

## Debugging Toolkit
- **Missing key or config errors:** The chatbot now surfaces backend issues with a red banner (for example, `OPENAI_API_KEY is not configured`). Address the root cause before retrying, otherwise each attempt will hit the same guard.
- **Direct API probe:** `pnpm debug:chatbot "<prompt>"` posts to `/api/chat` and prints the raw Server-Sent Event stream.
- **MCP health check:** `curl -X POST http://127.0.0.1:8002/mcp -H 'content-type: application/json' -d '{"jsonrpc":"2.0","id":"1","method":"list_tools"}'` should return available tools. If it fails, verify that widget assets were built and the server is running.
- **Quota issues:** The chatbot surfaces empty streams when OpenAI returns `AI_RetryError` (quota exceeded). Inspect the Next.js terminal output for error traces.
- **Widget rendering:** Look for `[Chat] Widget fetched from ...` in the server logs to confirm HTML resources were resolved.
